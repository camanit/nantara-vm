📚 NantaraVM — Dokumentasi Teknis & Arsitektur

Dokumen ini menjelaskan arsitektur teknis, status implementasi, panduan build, dan roadmap NantaraVM secara jujur dan transparan.

⚠️ Penting Dibaca Sebelum Mulai: NantaraVM saat ini adalah proyek Early Alpha. Banyak fitur yang digambarkan di sini adalah desain dan rencana implementasi, bukan fitur yang sudah berjalan. Bagian status di setiap bab akan menjelaskan kondisi terkini secara jujur.

Bab 1: Pengenalan & Visi Proyek

NantaraVM adalah proyek open-source untuk membangun MicroVM Hypervisor berbasis bahasa Rust yang aman, cepat, dan sovereign. Proyek ini terinspirasi oleh:

  • Firecracker (AWS) — Arsitektur MicroVM minimalis dengan cold boot sangat cepat
  • crosvm (Google) — Multi-proses sandboxing dan isolasi keamanan
  • Cloud Hypervisor (Intel) — Fitur enterprise seperti SEV-SNP dan ACPI modern

Bedanya: NantaraVM dibangun oleh engineer Indonesia, untuk kebutuhan cloud sovereign NKRI, dengan kode sumber terbuka sepenuhnya.

✅ Status Fase 0 (Fondasi): Selesai. Arsitektur modul, Cargo workspace, integrasi library KVM, dan website sudah tersedia.

Bab 3: Cara Build dari Source

⚠️ NantaraVM saat ini hanya bisa dikompilasi di Linux. Dependensi KVM (kvm-ioctls, vm-memory) membutuhkan kernel Linux. Di Windows, hanya stub mode yang aktif.

A. Build di Linux (Ubuntu/Debian)

# 1. Install Rust toolchain
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
source ~/.cargo/env

# 2. Install dependency sistem
sudo apt-get install -y build-essential git

# 3. Clone repository
git clone https://github.com/camanit/nantara-vm.git
cd nantara-vm

# 4. Build
cargo build

# 5. Jalankan (demo/stub mode jika tanpa vmlinux)
cargo run

B. Build di Windows (WSL2)

Instal WSL2 dengan Ubuntu, lalu ikuti langkah Linux di atas di dalam terminal WSL2. KVM di WSL2 membutuhkan Windows 11 atau Windows 10 Build 19041+ dengan Hyper-V. 

# Cek apakah KVM tersedia di WSL2 Anda
ls /dev/kvm
# Jika ada → KVM bisa digunakan
# Jika tidak ada → hanya stub/demo mode
💡 Catatan WSL2: Tidak semua konfigurasi WSL2 mengekspos /dev/kvm. Tergantung versi Windows dan apakah Hyper-V nested virtualization aktif.

Bab 4: Menjalankan Linux Guest (Target Fase 1)

⚠️ Fitur ini belum sepenuhnya berjalan. Ini adalah target implementasi Fase 1 yang sedang dikerjakan.

Setelah implementasi vCPU dan VirtIO block selesai, rencana penggunaan adalah:

# Jalankan dengan kernel Linux sederhana (target Fase 1)
./nantara-vm --kernel vmlinux --rootfs rootfs.ext4

# vmlinux = kernel Linux compiled (bukan disertakan di repo)
# rootfs.ext4 = disk image root filesystem guest

Cara Mendapatkan vmlinux untuk Testing

# Download kernel minimal untuk testing
# (panduan lengkap akan ditambahkan setelah Fase 1 selesai)
wget https://cdn.kernel.org/pub/linux/kernel/v6.x/linux-6.6.tar.gz

Bab 5: Menjalankan Windows 10 (Roadmap Jangka Panjang)

⚠️ Boot Windows 10 BELUM diimplementasi dan membutuhkan banyak komponen yang belum ada: UEFI/OVMF firmware emulation, VirtIO driver untuk Windows, virtio-gpu display output, dan ACPI table yang kompatibel Windows.

Ini adalah target jangka panjang (2026+). Komponen yang dibutuhkan:

  • UEFI/OVMF firmware emulation (BIOS virtual)
  • VirtIO Windows driver (VirtIO-win ISO dari Fedora)
  • virtio-gpu atau VGA emulation untuk display
  • ACPI tables yang kompatibel dengan Windows
  • noVNC WebSocket untuk akses display dari browser

Untuk kebutuhan menjalankan Windows 10 sekarang, rekomendasi kami adalah menggunakan:

  • Hyper-V (gratis, sudah ada di Windows 10/11)
  • QEMU/KVM di Linux (mature, battle-tested)
  • VirtualBox (cross-platform, GUI friendly)
