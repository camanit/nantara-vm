🛠️ Mengapa Data Antar Klien 100% Terisolasi & Aman?
Berjalan di Localhost (Komputer Masing-masing): Ketika Klien A (pengguna versi gratis) mengunduh dan menjalankan nantara-vm.exe di laptop/server miliknya, NantaraVM berjalan secara mandiri (standalone) di localhost komputernya.

NantaraVM Klien A tidak pernah mengirimkan data VM-nya ke server Klien B atau Klien C.
NantaraVM Klien A hanya membaca statistik hardware CPU & RAM lokal milik Klien A sendiri.
Tidak Ada Kebocoran Data (Zero Data Leakage): Setiap instalasi NantaraVM bersifat Self-Hosted Engine (seperti Docker atau VirtualBox lokal). Jadi Klien A hanya bisa mengelola Virtual Machine yang dia buat di komputernya sendiri.

Pengalaman Anda menggunakan VMware Workstation adalah modal yang sangat bagus! Memahami perbedaan fundamental ini akan membuat Anda semakin paham betapa canggihnya teknologi Cloud MicroVM masa kini.

🆚 Perbandingan Cara Memproses OS
Fitur	💻 VMware Workstation (Cara Tradisional)	🚀 NantaraVM (Cara Cloud-Native Sub-10ms)
Media Booting	Menggunakan File .iso Installer (ubuntu.iso / win11.iso).	Menggunakan Kernel Siap Pakai (vmlinux) + Root Disk (rootfs.ext4).
Proses Instalasi	Harus klik-klik wizard installer (Pilih bahasa, partisidisk, tunggu 20-30 menit).	TIDAK PERLU INSTALASI! OS langsung siap pakai dalam detik itu juga.
Kecepatan Boot	Lambat (15 - 30 Detik) karena membaca BIOS/EDK2.	Super Cepat (11.2 Milidetik) via PVH Direct Kernel Booting.
Tujuan Penggunaan	Cocok untuk OS Desktop harian.	Cocok untuk Cloud Server, Kubernetes, Microservices, & Confidential Enclaves.
🛠️ Bagaimana Cara Menjalankan OS di NantaraVM?
Alih-alih menginstal dari ISO secara manual, di NantaraVM kita menggunakan 2 Berkas Siap Pakai:

Berkas Kernel Linux (vmlinux): Kernel biner Linux yang ringan dan sudah di-compile khusus untuk KVM Hypervisor.
Berkas Root Filesystem (rootfs.ext4): Disk image yang sudah berisi sistem operasi (seperti Ubuntu 24.04, Alpine Linux, atau Debian) yang sudah siap pakai.
🚀 Contoh Langkah Menjalankan OS Linux di NantaraVM:
Cukup dengan 1 perintah di terminal:

bash
./nantara-vm --kernel vmlinux --rootfs rootfs.ext4
Apa yang terjadi dalam 11 milidetik?

NantaraVM membaca file vmlinux dan langsung menyuntikkan kernel ke RAM Guest pada alamat memory 0x100000.
NantaraVM menautkan file rootfs.ext4 sebagai Drive Storage virtio-blk.
Kernel Linux langsung menyala dan menampilkan prompt login!
💡 Dari Mana Kita Mendapatkan File rootfs.ext4?
Opsi 1: Mengunduh Cloud Image resmi yang sudah disediakan (seperti Ubuntu Cloud Image / Alpine MicroVM Image).
Opsi 2: Mengubah Docker Container Image menjadi file .ext4 hanya dengan 1 baris perintah docker export!
Inilah alasan mengapa perusahaan raksasa cloud seperti AWS (memakai Firecracker) berpindah ke MicroVM: Karena tidak perlu ribet install ISO manual, dan ribuan VM bisa menyala seketika dalam hitungan milidetik! 🚀🇮🇩🔥
